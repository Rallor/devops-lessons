# Блок 4.1 — Terraform: основи

**Час:** ~6 год · **Передумови:** Етап 3

## Навіщо це зараз
Ручні зміни в порталі не мають ні аудиту, ні відтворюваності. Перше, що має зʼявитися, — план, який показує різницю між бажаним і фактичним.

## Теорія
- Декларативний підхід проти імперативного; provisioning проти configuration management — межа з Ansible.
- HCL: resources, data sources, providers, locals; `for_each` проти `count` і чому `count` ламає адресацію.
- `init`, `plan`, `apply`, `destroy`; plan-файл через `-out` у CI.
- Пінінг версій: `required_version`, `required_providers`, `.terraform.lock.hcl` у git.
- `fmt`, `validate`, `tflint`; сканування IaC (`checkov` або `trivy config`).
- AI-генерація з заземленням: Terraform MCP Server і Azure MCP Server дають агенту актуальні схеми провайдера; апрув і `plan` лишаються за людиною.

## Завдання
1. Опиши в коді resource group, VNet і одну підмережу; пройди повний цикл init → plan → apply.
2. Додай `for_each` для трьох підмереж; видали середню і покажи в плані, що інші не перестворюються.
3. Зроби те саме через `count` і покажи різницю в плані — це аргумент для нотаток.
4. Запінь версії провайдера і Terraform; закоміть lock-файл.
5. Додай `fmt`, `validate`, `tflint` і сканер IaC у pre-commit.
6. Згенеруй один модуль за допомогою AI з підключеним MCP і без нього; порівняй, скільки правок треба в обох випадках. Запиши в `docs/notes/ai-iac.md`.
7. Зроби зміну в порталі руками і покажи її в `plan` — це твій перший дрейф.

## Критерії прийому
- [ ] Інфраструктура піднімається з нуля командами Terraform
- [ ] Версії запінені, lock-файл у git
- [ ] Лінтери й сканер IaC у pre-commit
- [ ] Порівняння `for_each` і `count` задокументоване
- [ ] Дрейф після ручної зміни видно в `plan`

## Пастки
- `apply` без `plan -out` виконує не те, що ти бачив: між ними стан міг змінитися.
- Провайдер без піна одного дня зламає все на мажорному оновленні.
- AI генерує аргументи, яких немає в поточній версії провайдера, — `validate` це ловить, память моделі ні.
- Ресурси, створені руками, Terraform не бачить, поки їх не імпортувати.

## Підказки
<details><summary>Підказка 1</summary>
`terraform plan -out=tfplan` і `terraform show -json tfplan | jq` дають машиночитний план — це знадобиться для перевірок у CI.
</details>
<details><summary>Підказка 2</summary>
`for_each` працює з map або set: ключ стає частиною адреси ресурсу, тому видалення елемента не зсуває решту.
</details>
