# Блок 3.5 — Стратегії деплою і rollback

**Час:** ~6 год · **Передумови:** 3.3, 3.4

## Навіщо це зараз
Відкат за хвилину цінніший за ідеальний тест перед релізом. Це треба не прочитати, а заміряти секундоміром.

## Теорія
- Rolling, blue-green, canary: механіка, вартість ресурсів, вимоги до моніторингу.
- Blue-green на двох VM: два набори контейнерів і перемикання upstream із `nginx -t` та reload.
- Feature flags: відділення релізу коду від релізу функціональності; борг старих прапорців.
- Rollback як redeploy попереднього digest; коли roll forward кращий.
- `/version` і відповідність digest між середовищами.

## Завдання
1. Реалізуй деплой у staging автоматично на merge в `main`.
2. Реалізуй prod-деплой за стратегією з ADR-011; для двох VM найпростіше blue-green через upstream.
3. Додай `/version`, який повертає git sha і час білду; перевір, що він збігається з digest у реєстрі.
4. Зроби реліз, потім відкат на попередній digest. Заміряй час від рішення до відновлення і запиши.
5. Додай feature flag для однієї ризикової зміни; покажи, що вимкнення прапорця не потребує деплою.
6. Зімітуй «поганий реліз»: зміна валить 30% запитів. Пройди цикл виявлення і відкату повністю, зафіксуй таймлайн.
7. Опиши в `runbook.md` процедуру відкату так, щоб нею міг скористатися хтось інший о третій ночі.

## Критерії прийому
- [ ] Staging деплоїться автоматично, prod — після approval
- [ ] Rollback заміряний і вкладається в 5 хв
- [ ] `/version` у проді відповідає задеплоєному digest
- [ ] Feature flag працює без деплою
- [ ] Процедура відкату в runbook читається без контексту

## Пастки
- Blue-green без міграцій, сумісних в обидва боки, робить відкат неможливим.
- Reload nginx без `nginx -t` кладе проксі разом із новою версією.
- Rollback «через git revert і повний білд» займає не 5 хвилин, а стільки, скільки триває пайплайн.
- Прапорець, який лишився назавжди, з часом стає гілкою коду, яку ніхто не тестує.

## Підказки
<details><summary>Підказка 1</summary>
Швидкий rollback можливий лише тоді, коли попередній артефакт уже існує: тримай останні N образів і не чисти їх агресивно.
</details>
<details><summary>Підказка 2</summary>
Перемикання upstream зручно робити симлінком на конфіг blue або green плюс reload — так відкат є однією командою.
</details>
