# Етап 3. Регулярні релізи → безпечна доставка (тижні 12–15)

## Тригер
Команда релізиться тричі на тиждень. Деплой — це ssh на сервер, `git pull` і білд прямо на проді. Хтось задеплоїв не ту гілку, міграція впала на половині, відкат зайняв дві години.

## Вимоги етапу
1. Кожен PR: lint → тести → build → scan; червоний пайплайн блокує merge.
2. Build once, deploy many: образ збирається один раз і просувається без перезбирання.
3. Артефакт immutable, має версію; версія в проді видна на `/version`.
4. Merge у `main` → staging автоматично; prod — через approval.
5. Міграції БД окремим кроком, зворотно сумісні, без даунтайму.
6. Rollback у prod ≤5 хв, відпрацьований на реальному релізі.
7. Жодних секретів у репозиторії й логах; токени CI з мінімальними правами.
8. CRITICAL CVE з фіксом блокує публікацію.
9. Сторонні actions запінені за SHA, workflow проходять статичний аналіз, небезпечні тригери не мають секретів.
10. Образи підписані, деплой перевіряє підпис.
11. Baseline пʼяти метрик DORA.

## ADR етапу
- **ADR-008.** Trunk-based + feature flags проти Git flow.
- **ADR-009.** Версіонування: semver, calver чи лише sha; хто ставить тег.
- **ADR-010.** CI-платформа: GitHub Actions, GitLab CI, Azure DevOps; Jenkins як легасі.
- **ADR-011.** Стратегія деплою на двох VM: rolling, blue-green через nginx, canary.

## Ворота етапу
Ментор (або скрипт) мерджить зламану зміну — ти відкочуєш prod за ≤5 хв із заміряним часом; міграція з перейменуванням колонки без 5xx; `gitleaks` по історії чистий.
