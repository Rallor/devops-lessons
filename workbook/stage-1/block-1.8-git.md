# Блок 1.8 — Git

**Час:** ~4 год · **Verify:** `verify/stage-1/90-git.sh` · **Передумови:** —

## Навіщо це зараз
Усе, що ти налаштував руками, має лежати в репозиторії. На Етапі 2 цей репозиторій стане специфікацією для Ansible, а на Етапі 3 — джерелом деплою.

## Теорія
- Модель blob/tree/commit/ref; чому гілка — просто вказівник.
- `merge` проти `rebase`; чому не можна rebase публічну гілку; `rebase -i` (squash, fixup).
- Конфлікти: маркери, `git mergetool`, стратегія вирішення.
- `cherry-pick`, `reflog`, `blame`, `bisect`, теги.
- Hooks: pre-commit, commit-msg, pre-push; локальні проти server-side; фреймворк pre-commit.
- `.gitignore` з першого коміту: `.env`, ключі, стан.

## Завдання
1. Створи репозиторій `infra` зі структурою: `systemd/`, `nginx/`, `scripts/`, `docs/`, `runbook.md`.
2. Перенеси туди все, що вже налаштовано руками, і додай `.gitignore` з секретами й тимчасовими файлами.
3. Увімкни захист `main`: заборона прямого push, PR обовʼязковий.
4. Постав pre-commit із трьома хуками: `shellcheck` для скриптів, перевірка формату commit-повідомлення, `gitleaks` на секрети.
5. Навмисно спробуй закомітити файл із паролем — переконайся, що хук блокує.
6. Створи гілку, зроби три коміти, зведи їх у один через `rebase -i` і змерджи через PR.
7. Зімітуй конфлікт (дві гілки правлять один рядок nginx.conf) і розвʼяжи його.
8. Видали коміт «випадково» (`reset --hard`) і віднови через `reflog`.
9. Постав тег `v0.1-stage-1` на стан кінця етапу.

## Пастки
- Секрет, закомічений і видалений наступним комітом, лишається в історії назавжди — переписування історії або ротація секрету.
- `git add .` тягне `lab.env` і ключі, якщо `.gitignore` написаний після першого коміту.
- `rebase` на гілці, яку хтось уже забрав, ламає роботу колеги. На курсі колега — це майбутній ти на іншій машині.

## Підказки
<details><summary>Підказка 1</summary>
Формат повідомлень простіше зробити через Conventional Commits і хук `commit-msg` із регуляркою. Це знадобиться на Етапі 3 для генерації CHANGELOG.
</details>
<details><summary>Підказка 2</summary>
`git reflog` показує всі стани HEAD, навіть ті, до яких уже немає гілки. `git reset --hard <sha з reflog>` повертає назад.
</details>
