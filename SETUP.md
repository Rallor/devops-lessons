# Налаштування за 30 хвилин

## 1. Стенд

Azure VM, Ubuntu 26.04 LTS, розмір B2s. Бюджет-алерт створюєш **до** віртуалки: Cost Management → Budgets, поріг на свою суму, сповіщення на пошту.

На стенді відразу:

```bash
sudo touch /etc/devops-lab      # запобіжник: без цього файлу incidents/inject.sh відмовиться працювати
```

## 2. Репозиторій

```bash
cp lab.env.example lab.env      # заповнити своїми значеннями; lab.env у .gitignore
./verify/run.sh 1               # на старті майже все червоне — це нормальна відправна точка
```

Червоний звіт першого дня збережи в `docs/evidence/day-0.md`. Наприкінці етапу приємно подивитися.

## 3. CI

У налаштуваннях репозиторію додай секрети: `LAB_HOST`, `LAB_DOMAIN`, `LAB_SSH_USER`, `LAB_SSH_PORT`, `BASTION_HOST`, `LAB_SSH_KEY`.

Окремий ключ для CI, не твій особистий. Користувач на стенді з мінімальними правами: те, що потрібно перевіркам, і нічого більше.

## 4. AI-тьютор

Створи окремий простір (Claude Project або еквівалент). Системний промпт — `prompts/00-tutor-system.md`. Додай у контекст: план курсу (PDF), `workbook/` поточного етапу, `templates/`.

Для тесту (`prompts/04-quiz.md`) — **окремий чат без цих файлів у контексті**. Інакше ти екзаменуєш не себе, а свій репозиторій.

## 5. Ритм

П'ять сесій на тиждень по дві години краще, ніж одна десятигодинна субота: інфраструктура вимагає повторів, а не марафонів. Один день на тиждень — без нового матеріалу, тільки `verify`, борги й записи в `progress.md`.

## Що коли зламається

- `verify` червоний, а руками все працює → перевір, звідки запускаєш: з ноутбука видно не те саме, що з раннера. Це не баг перевірки, це і є суть.
- Не встигаєш за планом → нормально. Не пропускай блоки, розтягуй календар.
- Рахунок зростає → `az vm deallocate` після кожної сесії, і подивись, чи не лишився публічний IP, диск або NAT Gateway.
