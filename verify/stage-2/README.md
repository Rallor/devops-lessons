# Перевірки етапу 2

Скрипти цього етапу пише студент — і це частина програми, а не недоробка курсу.

Причина: починаючи з Етапу 4 стенд роздвоюється на ADR (Terraform чи OpenTofu, App Service чи VMSS, Gateway API у трьох реалізаціях). Готовий скрипт під один варіант мовчки ухвалив би рішення за тебе.

## Як писати

1. Візьми вимоги етапу з `workbook/stage-2/README.md`. Кожна вимога — одна перевірка.
2. Формулюй перевірку від вимоги, а не від інструмента. «Рестарт інстансу не дає користувачу помилок» істинне і для nginx, і для slots, і для Kubernetes. «В upstream два бекенди» — ні.
3. Використовуй `verify/lib/common.sh`: `check`, `check_fails`, `ok`, `bad`, `summary`. Приклади — у `verify/stage-1/`.
4. Кожна перевірка має падати з осмисленим повідомленням: що саме не так, а не просто exit 1.
5. Те, що автоматизувати неможливо, — у `manual.md` з артефактом на кожен пункт.

## Критерій готовності

Перевірка вважається написаною, якщо ти зламав відповідну річ навмисно і скрипт це помітив. Перевірка, яка ніколи не була червоною, нічого не доводить.
